# Feature catalogue

The full machine-readable catalogue lives in [`docs/feature-catalogue.json`](docs/feature-catalogue.json). It is generated by `npm run catalogue` from `src/content/catalogue.ts`.

How to read it:

- **implemented** entries are built from the real registries in the code: event types, toys, AI goals, planner operators, dialogue topics, the cast, poses and debug overlays. Each one exists and is exercised by a test or the smoke test. They can't drift from the game, because they come from the same data.
- **partial** means a version of it exists but is thinner than the description.
- **planned** entries are candidate ideas for the backlog. They are **not** in the game.
- Combinations such as personality × toy × place × weather produce a huge number of situations at runtime. They are deliberately **not** counted as separate features.
- The generator deduplicates by category and name. `tests/catalogue.test.ts` checks that IDs are unique, every one of the 40 categories is covered, and every event and toy in the code appears as implemented.
